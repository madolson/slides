**This deck is generated. Do not hand-edit it.** The builder always starts from a fresh copy of

## The talk

Nerdearla Argentina 2026, Buenos Aires, 22-26 September. Free, hybrid, ~50k attendees,
**explicitly not developer-only**, parallel tracks in Spanish and English. That last part drives
the structure: the deck opens with what Valkey even is, which The Vertical Scaling wall never had
to do.

Thesis, from the abstract: everyone reaches for a bigger machine first; that works until it
doesn't; scaling out has its own history of pain; neither axis is optional. Then what the community
did to make both boring, and how any of it gets measured.

## Everything on the template

Four slides used to be hand-drawn on the stock `Holding` layout, and 25 more sat on stock
`Title Only` / `Title + Cont`. All 36 are now on `Valkey *` layouts:

- **Slides 1, 34, 35, 36 are rebuilt on real layouts** rather than retexted. A design that exists
  as a layout should be used as one: the decoration is inherited, the geometry cannot drift, and the
  slide holds nothing but its text.
- **The other 25 are retargeted, not rebuilt.** `retarget_layouts()` swaps the slide's
  layout *relationship*, because python-pptx has no API for changing a slide's layout. This is only
  safe because the audit showed 24 of them use the title placeholder and nothing else, with content
  as loose shapes and charts; `Valkey Title Only` has the same title placeholder at the same
  geometry. It **refuses** any slide using a body placeholder rather than quietly reflowing it.
- Then `drop_second_master()` and `strip_stock_layouts()` run. Both refuse if a slide still
  references what they are deleting, and that refusal is the safety net. The builder asserts no
  slide is left on a non-Valkey layout.

Order is not optional: move the slides, *then* delete. File size went 3.99 MB -> 3.4 MB, mostly the
stock layouts' full-bleed background pictures.

### Two template bugs this surfaced

Both are fixed in `build_placeholder_deck.py`, which is where the layouts are defined. **The
placeholder deck itself has not been rebuilt**, so `Valkey placeholder slides.pptx` still carries
the old geometry; re-run that builder to pick the fixes up.

1. **`Valkey Title Band` was sized for a one-line title.** It put the subtitle 799070 EMU (62.9pt)
   below the title top, and two lines at 40pt with 1.1 spacing need 88pt, so line two printed
   straight through the subtitle. Any real talk title wraps in that 7.42in column. The layout now
   budgets two lines and stacks the subtitle, speaker and role from there.
2. **`Valkey List Rows` bars do not delete with the row.** The card fill belongs to the placeholder
   so it goes, but the accent bar is a static layout shape and is inherited regardless, leaving a
   stub of Valkey blue on white. The layout's docstring claimed the opposite. A slide using fewer
   than five rows must mask the leftovers with a `LIGHT_1` rectangle; `slide_goals()` does.

### The operator slide

Slide 33 is the only slide about *running* Valkey rather than about Valkey, and it closes the
"going out" section. It earns its place because everything from 22 to 32 is a command somebody has to
issue in the right order, and the operator is who issues them.

It sits on **`Valkey Three Features`**, a layout added for this slide: a version eyebrow under the
title, then three numbered features on white. Distinct from `Valkey Three Box`, which is three filled
cards for a comparison. The numerals and their accent rules are static layout decoration; only the
per-column heading and body are placeholders.

**The version matters and was wrong in an earlier pass.** The operator is at **v0.6.0** (1 Sep), not
v0.1.0, which was the first alpha back on 11 May. Six releases in four months, with breaking API
changes in at least v0.4.0 and v0.5.0, so this slide dates quickly: re-check the version and the
feature names before presenting. The project's own front page says it is not production ready and
that data loss can be expected, which is why the eyebrow reads "alpha, not production ready" rather
than selling it.

The three features are picked to land in *this* talk, not to summarise the project. Feature 1 is the
slot migration the previous ten slides just explained, now driven by a controller:

| # | Feature | Drawn from |
|---|---|---|
| 1 | Scaling: `spec.shards`, slot rebalancing on scale-out, slot draining on scale-in | v0.1.0 notes; `spec.shards` required from v0.3.0 |
| 2 | Rolling upgrades and failover: replicas before primaries, proactive failover first | v0.1.0 and v0.2.0 notes |
| 3 | TLS and ACLs declared in the spec, ACL changes applied without a restart | `spec.networking.tls` from v0.5.0/v0.6.0; `ACL LOAD` from v0.5.0 |

A fourth candidate that did not make it: **observability** (Prometheus metrics from v0.3.0, status

## The dropped-run bug

`set_runs()` deep-copies a run element to preserve formatting and then appended it to the
paragraph. On any paragraph that already carried an `a:endParaRPr`, that put the run *after* it,
violating the `pPr?, EG_TextRun*, endParaRPr?` sequence, and **PowerPoint silently dropped the
run**. It hit 9 paragraphs on 7 slides: the conference line on the old title slide, two whole slide
titles, both two-box cards on the "up"/"out" frames, the second architectural goal, and the closing
question. Slide numbers in that report predate the current ordering.

Nothing in this repo caught it. python-pptx read the text back, `dump_deck.py` printed it, and
`mock_render.py` drew it. The deck was correct in every tool here and missing text on screen.
`set_runs()` now inserts with `end.addprevious(new_r)`, and `audit_paragraph_order()` fails the
build if any paragraph regresses. See pitfall 20 in `../generation/slides-skill.md`.

**If text is reported missing and every tool here says it is present, check the `a:p` child order
first.** Do not re-render; the renderer cannot see this class of bug.

## Fonts: Arial only

The donor's theme major font was **Play** and its bulleted paragraphs set `buFont typeface="Play"`.
Play is a Google font. It is not on a conference laptop, so PowerPoint substitutes silently and a
title that looked right here reshapes in the room. The builder now rewrites **both** theme fonts to
Arial (`retypeface()`, 285 Play references and 626 Century Gothic), pins Arial on every run
including the 28 carried-over donor slides (`pin_font()`, 234 runs), and fails the build if either
a run is off-font or a banned typeface survives anywhere in the package (`audit_fonts()`).

This is a deliberate departure from `../generation/slides-skill.md`'s three-font rule, which keeps Play and
Century Gothic in the theme. Nothing in this deck renders in either, so keeping them only preserved
the substitution risk. The font pass runs **last, over the finished deck**, so a slide added later
cannot be missed.

## Editing notes

- **Resolve layouts by name.** Never by index.
- Charts on slides 6, 8, 9, 10, 23, 24. Slide 6 is built from scratch; the rest are the donor's.
  Use `replace_series()` / `rename_series()`, which re-supply the full series set, and go through
  `categories_of()` so blank category labels survive the round trip.
- `clone_slide()` deep-copies a shape tree and **refuses anything carrying a relationship**
  (pictures, charts). That is why slide 27 could be cloned from 28 and why the chart slides cannot.
- Diagram slides use `ROUNDED_RECTANGLE`, not the square-corner house style. Match what you edit.
- The new slides use `SHORT_CARD_H` (2.84in) rather than the placeholder deck's `CARD_H` (3.9in),
  which is sized for a denser card and leaves a third of these empty.
- `card_with_mark()` is the card variant whose top slot takes a brand logo instead of an icon. A
  logo has its own aspect ratio and must never be squared off into the icon slot, which is why
  `card()` could not just take a filename.
- **Fill alpha is hand-written XML.** `translucent()` appends `<a:alpha>` to an `<a:srgbClr>`;
  python-pptx has no API for it, and a theme colour writes `<a:schemeClr>`, which cannot carry it.
  That is why the flame graph bands use `VALKEY_BLUE` as explicit RGB rather than `ACCENT_1`.
- `reorder_and_prune()` sets the order and deletes unlisted slides in one pass. Doing either step
  first corrupts the other's indices.
